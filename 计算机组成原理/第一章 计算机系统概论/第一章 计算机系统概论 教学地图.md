## 总问题

**一台能够自动执行程序的计算机，为什么需要这些组成部分，如何协同工作，又怎样评价其能力？**

逻辑主线：**人工计算的局限 → 自动计算与存储程序 → 系统抽象与硬件分工 → 问题转化为指令 → 取指、译码、执行 → 速度与容量评价。**

## 01｜计算机发展：从人工计算到存储程序

**一句话目标：** 理解自动化计算的需求如何推动机械计算工具、电子计算机与存储程序思想的出现。

**核心知识点（一句话定位）**
- [ ] **计算工具演进：** 算筹、机械计算器等逐步把人工计算步骤交由工具实现。
- [ ] **早期电子计算机：** ENIAC 的电子计算能力与人工设置程序的局限，应同后续存储程序方案区分。
- [ ] **二进制与存储程序：** 二进制解决信息表示问题，存储程序解决指令保存和自动取用问题。
- [ ] **技术代际：** 电子管、晶体管、集成电路和大规模／超大规模集成电路推动硬件演进。
- [ ] **发展规律及背景：** 摩尔定律、课件讨论的技术趋势与我国计算机发展内容应完整覆盖。

**必须理解：** 电子化 ≠ 程序自动保存；二进制 ≠ 存储程序。能从早期机器的编程局限解释后者的动机。

**配套材料：** 发展时间线、ENIAC／EDVAC 对照、课件中代表机器与技术节点。

**随后补充：** 机械器件实现原理、摩尔定律的适用边界、相关历史细节与前沿观点。

## 02｜系统层次：复杂功能如何被组织

**一句话目标：** 理解计算机如何借助硬件、软件及层次抽象，为上层提供可使用的能力。

**核心知识点（一句话定位）**
- [ ] **硬件与软件：** 硬件实现物理运算和控制，软件描述任务与行为。
- [ ] **语言层次：** 高级语言、汇编语言和机器语言体现不同抽象层级。
- [ ] **翻译过程：** 编译、汇编等负责代码翻译，不等同于操作系统运行服务。
- [ ] **虚拟机器：** 每一层对上提供一定能力，同时依赖下层支持。
- [ ] **操作系统层：** 操作系统是系统软件和功能接口层，并非机器代码翻译必须经过的一步。
- [ ] **微程序机器：** 课件最底层的微指令控制概念应与机器指令区分。

**必须理解：** 「功能依赖／抽象层次」与「语言翻译流程」是两种不同关系；课件的层次图不是一条必经的编译流水线。

**配套材料：** 1.1 层次结构原图；高级语言到机器指令的示例；程序请求系统服务的示意。

**随后补充：** 微程序控制的电路与实现细节、不同语言运行模型、操作系统 API。

## 03｜硬件总体结构：用五大部件实现自动计算

**一句话目标：** 从自动执行程序所需功能出发，理解冯·诺依曼计算机的五大部件和结构演变。

**核心知识点（一句话定位）**
- [ ] **存储程序：** 指令与数据均能存于存储器，通过地址访问。
- [ ] **指令表示：** 在课件简化模型中，机器指令包含操作码和地址码。
- [ ] **五大部件：** 运算器、控制器、存储器、输入设备、输出设备分担计算、控制、存储和交互。
- [ ] **部件组合：** 简化教学模型中 CPU = 运算器 + 控制器，主机 = CPU + 主存。
- [ ] **结构演变：** 从以运算器为中心转向以存储器为中心，改善输入输出与存储器的数据交换组织。
- [ ] **信息与控制流：** 数据通路、地址传送和控制信号不是同一种信息流。

**必须理解：** 从「程序要保存、操作要执行、步骤要协调、结果要交互」推导部件，而不只背五个名称；结构演变是真实通路和控制关系改变，不只是元件改名。

**配套材料：** 1.2 P6–9 的两种结构图、现代硬件框图、数据通路箭头。

**随后补充：** 总线和实际硬件连接的细节、现代 CPU 与教学简化模型的差别。

## 04｜指令与程序：把数学问题翻译成机器操作

**一句话目标：** 理解问题如何从数学模型、算法转化为机器指令及存放于主存的程序。

**核心知识点（一句话定位）**
- [ ] **问题求解链：** 建模确定计算对象，算法组织步骤，程序表达成可执行指令。
- [ ] **指令系统：** 规定处理器可识别的机器操作与编码规则。
- [ ] **具体指令：** 操作码说明做什么，地址码等操作数字段说明针对什么对象。
- [ ] **程序：** 按执行逻辑组织的指令序列，不是无序指令集合。
- [ ] **课件六条示例指令：** 加法、乘法、取数、存数、打印、停机；不得误记为减法替代乘法。
- [ ] **原始案例：** `sin x` 说明问题到程序的转换，`ax²+bx+c` 比较不同运算组织方式。
- [ ] **存储表示：** 能阅读课件 P16–17 的二进制指令字段、地址 0–12 的完整程序表。

**必须理解：** 一组有限类型的机器指令可以通过不同操作数、不同指令顺序执行不同任务；表达式变形可减少中间结果保存和访存。

**配套材料：** `ax²+bx+c` 两种程序的逐步状态表、P16 指令编码与 P17 完整存储表。

**随后补充：** Horner 法一般化、立即数与复杂寻址方式、乘法指令内部如何实现。

## 05｜部件与执行：程序究竟怎样运行

**一句话目标：** 追踪一条机器指令在 CPU 与主存间的完整数据流，并理解控制信号如何协调执行。

**核心知识点（一句话定位）**
- [ ] **存储结构：** 存储体由带地址的存储单元构成，每个存储元件保存一位二进制信息。
- [ ] **主存寄存器：** MAR（Memory Address Register）保存本次访存地址，MDR（Memory Data Register）暂存读写数据。
- [ ] **运算器：** ALU（Arithmetic Logic Unit）执行运算；ACC（Accumulator）、X、MQ 等寄存器保存参与运算的数和结果。
- [ ] **控制器：** PC（Program Counter）保存待取指令地址，IR（Instruction Register）保存当前指令，CU（Control Unit）发出控制信号。
- [ ] **执行循环：** PC→MAR→主存→MDR→IR 完成取指，译码后按指令要求执行相应操作。
- [ ] **PC 更新：** 顺序执行在课件一字一指令模型中可加 1；跳转时改写为目标地址；PC 不是地址栈。
- [ ] **取数与存数：** LOAD 按地址把主存数据送往 ACC，STORE 把 ACC 数据按地址写回主存。
- [ ] **数据流与控制流：** CU 控制传送与计算时机，不意味着所有数据需要经过 CU。
- [ ] **乘除法寄存器：** 乘法涉及部分积、移位与累加，ACC/MQ 可联合保存双倍字长结果；除法区分商与余数。

**必须理解：** 在完整示例中分清「指令地址／操作数地址」和「地址／数据」，并能追踪 PC、IR、MAR、MDR、ACC 的状态变化。

**配套材料：** 1.2 P19–20 存储器结构、P21–27 运算器及笔算乘法、P28–34 取指和 LOAD/STORE 原图；使用分帧箭头演示。

**随后补充：** 移位加法／除法算法的逐周期细节、指令周期的进一步分类、微程序控制实现。

## 06｜性能：如何评价一台计算机

**一句话目标：** 根据位宽、存储组织和时钟执行模型，定量解释容量与执行速度。

**核心知识点（一句话定位）**
- [ ] **三种字长：** 机器字长、存储字长和指令字长分别刻画处理数据、存储字与指令的位数，未必相等。
- [ ] **信息单位：** bit 是比特（位），Byte 是字节，1 Byte = 8 bit。
- [ ] **存储容量：** 在课件按字编址模型中，容量 = 可寻址单元数 × 存储字长；MAR 位数与 MDR 位数用于示例推算。
- [ ] **时钟与主频：** 时钟周期是同步电路时序基本周期，主频是其倒数（Hz、MHz、GHz）。
- [ ] **CPI：** 平均每条指令消耗的时钟周期数，单位是周期/指令，不是 GHz。
- [ ] **执行时间：** CPU 时间 = 指令数 × 平均 CPI ÷ 主频。
- [ ] **其他指标：** MIPS、IPC、FLOPS 衡量不同对象，吉普森法基于不同指令比例和时间计算平均性能。

**必须理解：** 速度不能只看主频；计算容量或时间时应始终带单位，避免 bit／Byte 和 GHz／MIPS 混淆。

**配套材料：** 主频—CPI—执行时间动态示意；容量例题；课件 P35–38 性能指标表。

**随后补充：** 不同架构性能指标的局限、现代基准测试方法与前沿处理器主题。
